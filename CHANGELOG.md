## [Unreleased]

### Added
- **IR boolean extrude modes (cut / intersect):** `ExtrudeFeature` gains a `mode` (`union` | `cut` | `intersect`) so an extruded profile can be subtracted from or intersected with the running solid — arbitrary pockets, slots, and trims beyond the existing axis-aligned `hole`. The first extrude must be a union, and a boolean that empties the solid is rejected with a clear error. Editable/summarised in the Feature Timeline. Golden-tested: a 20×20 pocket cut through a 40×40×20 block leaves 28 000 mm³; a 40×40×20 ∩ 20×20×40 intersection is exactly 8 000 mm³; first-cut and erase-everything cases raise. 5 new tests.
- **IR plane-offset extrude (stacked/flanged parts):** `ExtrudeFeature` gains an `offset` field that shifts the start of the extrusion along the plane normal, so a body can begin where an earlier one ended. Unioned offset extrudes build stepped multi-body parts (lids, shouldered standoffs) without a boolean feature — previously impossible since every extrude started at the sketch plane. Editable/summarised in the Feature Timeline. Golden-tested: a 40×40×5 base + a 20×20×10 shaft at offset 5 gives exactly 12 000 mm³ and a 15 mm-tall bbox; a zero offset still overlaps as before. 3 new tests.
- **IR `chamfer` feature:** the Feature Program gains a `chamfer` op (chamfer every edge parallel to an axis by a length), mirroring `fillet` — kernel executor with the same too-large-for-the-wall guard and a no-op skip warning at length ≤ 0. Editable in the Feature Timeline (length + axis) and summarised there. Golden-tested against the closed-form removed-volume (W·L·H − 2·c²·H for the four vertical edges of a box) plus an oversize-failure case and a compile-API round-trip. 4 new tests.
- **Sandboxed freeform text-to-CAD generation (M2.5):** a new capability where the AI authors a CadQuery script that the engine executes to produce a part — for organic/swept/lofted/complex-boolean shapes the parametric templates cannot express. Integrates the approach of [earthtojake/text-to-cad](https://github.com/earthtojake/text-to-cad) (MIT) and build123d, implemented on the app's existing CadQuery/OpenCASCADE kernel (attribution in `NOTICE.md`). Defence-in-depth safety: a static AST guard (`domain/script_guard.py` — import allow-list of cadquery/math/numpy, no dunder attribute access, no dangerous builtins, requires a `result` assignment) rejects obvious escapes before anything runs; the runner (`adapters/cad/freeform_runner_main.py`) executes the script in a **separate process** with a restricted `__builtins__`, an audit hook blocking process-spawning and networking, and a hard wall-clock timeout enforced by the parent (`cadquery_freeform.py`). Results are **non-parametric mesh parts** — they load into the viewport beside IR parts but are not editable in the Parameters panel — with volume/bbox measured from the real B-rep, so ADR-0003 (numbers come from tools, never model text) holds for the freeform path too. New `POST /api/v1/freeform` (+ get and STEP/STL/OBJ/GLB/3MF export), a `generate_cad_script` AI tool (offered only when the freeform service is wired), and a renderer path that loads the generated mesh from a chat action. 33 new tests (guard rejection matrix + real-subprocess service/API/tool + renderer). **Security caveat, stated honestly:** Python cannot be fully sandboxed in-process; this is best-effort defence-in-depth, not a hardened boundary — true isolation (container/VM) is future work gated on Docker.
- **Data-plane groundwork (M2.3):** generated the **initial Prisma migration** offline from the canonical schema (`prisma/migrations/0001_init/migration.sql` + `migration_lock.toml`) so the Postgres data plane can be deployed with `prisma migrate deploy` the moment a database URL is configured. Added **`CloudSyncQueue`** — an offline-first background backup layer over the existing `CloudService` port that dedupes queued pushes by project id (latest document wins), retries failures with exponential backoff, no-ops cleanly under the local-only provider, and is disposed on quit — wired to new `cloud:queueProject` / `cloud:syncStatus` IPC channels. The local `.efproj` file remains the source of truth (ADR-0004); cloud backup is best-effort and never blocks local work. 5 desktop tests. Applying the migration to a live Postgres still needs Docker, and a real Supabase round-trip needs credentials — both user actions.
- **Involute spur-gear template (M2.1):** the IR gains a `GearProfile` sketch-profile kind that the kernel expands into a closed involute-gear outline at compile time (`gear_outline`) — base/pitch/addendum/root circles, involute flanks sized so the tooth thickness at the pitch circle is exactly half the circular pitch, with a radial drop below the base circle and a root arc joining adjacent teeth. Because the outline is generated from the parameters at compile time, the **tooth count is a live parameter** (a fixed polygon can't express that). The new **Spur Gear** template exposes module, teeth, face width, bore, and pressure angle, with an undercut advisory below 17 teeth — the fifth template, and the first to extend the IR's sketch vocabulary. No simple closed-form volume exists, so the golden tests bound the compiled B-rep volume between the root and addendum cylinders and assert the exact key radii and tooth count. 13 new tests.
- **Per-feature field editing (M2.4):** expanding a feature in the Feature Timeline now reveals an inline editor for its scalar fields — expression/number fields as text inputs (commit on Enter/blur), enum fields (axis, plane) as selects — backed by a new `PATCH /api/v1/parts/{id}/features/{featureId}` endpoint (`PartsService.patch_feature`). The edited feature is re-validated and the program compiled before committing: `op`/`id` are immutable, and unknown fields, invalid enum values, or geometry the kernel rejects all fail with a 400/422 and leave the stored part unchanged. Complex fields (sketch profiles, polygon points, shell open-faces, hole spread axis, extrude sketch reference) are deliberately left out of the inline editor rather than shown with a partial/fake control — they remain editable through the AI and raw IR. With reordering, this completes M2.4. 13 new tests (engine service/API incl. immutability + unchanged-on-failure guarantees, renderer field-descriptor/store/component).
- **Reorderable Feature Timeline (M2.4):** the timeline is no longer read-only — each feature has ▲▼ controls that move it one slot up or down, reordering the IR and recompiling through a new `POST /api/v1/parts/{id}/features/reorder` endpoint (`PartsService.reorder_features`). The endpoint validates that the ids are a permutation of the part's features and compiles the reordered program *before* committing it, so an order the kernel rejects (e.g. a fillet or hole placed before its extrude) fails with the geometry error and leaves the stored part untouched. The renderer store's `moveFeature` computes the swap, calls the engine, and syncs the viewport/project on success. 7 new tests (engine service/API incl. the unchanged-on-failure guarantee + renderer client/store/component).
- **Streaming chat responses (M2.2):** a new `POST /api/v1/ai/chat/stream` endpoint streams `ChatStreamEvent`s as newline-delimited JSON over chunked HTTP, so assistant replies render token-by-token instead of appearing all at once. The `AIProvider` port gains a `stream()` method with a default single-chunk wrapper (every provider streams for free); `StubProvider` streams word-by-word and `ClaudeProvider` streams real Anthropic token deltas through the manual tool loop, emitting `action` events as tools execute. The renderer's `EngineClient.chatStream` is an async generator that parses the NDJSON body; the chat store accumulates deltas into a live assistant bubble and finalizes on `done`, while preserving the offline delivery queue for failures that occur before the first chunk. Chunked HTTP was chosen over a raw WebSocket deliberately — for request-scoped one-way streaming it reuses the existing bearer-token header, CORS rules, single error envelope, and mockable `fetch` transport, with no bidirectional need. **Rebuild-progress streaming was intentionally not built:** a rebuild is a single ~160 ms kernel call with no genuine intermediate progress, so a progress indicator would be fabricated — deferred until rebuilds are slow enough to instrument real kernel stages. 12 new tests (engine provider/endpoint + renderer client/store).
- **Reviewable AI edit diffs (M2.2):** the `update_part_parameters` tool no longer mutates a part directly — it *proposes* a validated change. The engine gains `ParamDiffEntry` (old→new per parameter, with label/unit) and `PartsService.preview_params`, which validates against each parameter's range but never recompiles or mutates the part (no-op values are dropped). `ChatAction` carries `diff` + `pending`; the chat UI renders an Apply/Discard diff card, and only **Apply** fires the real PATCH → geometry swap → project-doc persist (via a new `parametricStore.applyDiff` sharing scene-sync logic with `refreshPart`). This closes the M1.3 deferral (AI edits as reviewable diffs before apply) and upholds ADR-0003 — proposed numbers still originate from validation, and nothing changes the model without explicit user consent. 15 new tests (engine preview/tool-loop round-trip + renderer store + first `ChatPanel.test.tsx` component test).
- **Feature Timeline panel (M2.4):** a read-only, ordered view of the selected parametric part's Feature Program — each feature shown with an op glyph, its id, and a per-op summary (sketch plane/profile, extrude distance, hole ⌀/count, fillet radius, shell wall + open faces). Makes the model's construction recipe (the IR the AI and parameter editor manipulate) visible in the UI. Header phase badge corrected to Phase 2.
- **Standoff / spacer template (M2.1):** fourth parametric part — a round standoff/spacer (cylinder with a concentric through-bore), golden-tested against the closed-form tube volume. Fits the existing IR (circle sketch + extrude + hole); PCB-mount and general-spacer use.
- **Shell feature + Enclosure template (M2.1):** the IR gains a `shell` feature (hollow a solid to a wall thickness, removing named faces) — the first extension of `efir/1` beyond the MVP set. The kernel executor guards against a real CadQuery footgun (it silently returns the un-hollowed solid when the wall is too thick) via a volume-decrease check. First part it enables: an **Enclosure / project box** template (open-top hollow box with a solid floor and rounded corners), golden-tested against the closed-form cavity volume. Templates now number three (bracket, mounting plate, enclosure).
- **Mounting Plate template (M2.1):** second parametric part in the library — a rectangular adapter/mounting plate with a symmetric 4-corner hole pattern (built from two linear hole rows), an independent center bore, and optional rounded corners, built entirely on the existing `efir/1` feature set (no kernel changes). Golden-tested against closed-form volume, a corner-fillet removal formula, and hole-symmetry; validates the template registry as a genuine plugin seam — both the Claude tool loop and the offline stub pick up new templates automatically via `list_part_templates`.
- **MVP polish (M1.4):** print estimates accept a live parametric `partId` (exact B-rep volume/bbox — no temp files) alongside mesh paths; every estimate now carries a lay-flat orientation hint (labelled bbox heuristic); multi-material 3MF export mixes imported meshes and parametric parts; Flashforge panel estimates and bulk-exports parametric parts. GitHub Actions CI workflow committed (TS suites + engine ruff/mypy/pytest on Python 3.12). MVP acceptance checklist completed in `docs/06-mvp-plan.md` with deviations recorded. **Phase 1 MVP complete.**
- **AI design pipeline (M1.3):** engine capabilities exposed to AI providers as tools (`AiToolbox`: list templates, create part, update parameters — every number originates from the CAD kernel); Claude provider gains a manual tool-calling loop (parallel tool results, error propagation, iteration cap); the offline stub deterministically handles template design commands so the full chat→part flow works with zero credentials. Chat responses carry `actions`; the renderer auto-loads created parts into the viewport/project and refreshes edited ones, with action chips in the chat.
- **Parametric CAD core (M1.2):** Feature Program IR v1 (`efir/1`) with a safe AST expression evaluator; CadQuery/OpenCascade kernel (CadQuery 2.8 on Python 3.12, lazy import, exact B-rep mass properties, RawMesh transport, actionable geometry errors); L-Bracket template with engineering checks; parts API (templates, create/compile, validated live parameter patches, STEP/STL/3MF/OBJ/GLB export). Renderer parameter editor with sliders, debounced ~160 ms live rebuilds, undo/redo, mass/warnings display, and STEP export; parametric parts persist in `.efproj` and recompile on open. Kernel golden-tested against closed-form volumes.
- **Flashforge workspace (M0.8):** curated material library (10 materials with density/strength/modulus/temps/cost) and 6 Flashforge printer profiles (incl. AD5X 4-material filament-switching and IDEX machines), schema-validated at load; material-compatibility engine (adhesion-family rules + nozzle-window/bed-delta escalation with human-readable reasons); first-order usage estimates (mass/cost/fit with explicit assumptions, watertight detection) and purge-tower estimates (tool-change model per multi-material system); multi-material 3MF export with per-part color/material (FlashPrint-compatible). Renderer Flashforge panel (printer select, slot setup, per-part assignment, warnings, estimates, export) with printer build volume + sized bed grid drawn in the viewport; all workspace state persists into `.efproj` documents.
- **Blender integration & conversion (M0.7):** Blender detection (EFC_BLENDER_PATH → PATH → versioned Program Files scan, cached version probe), detached GUI launch, headless Python script execution with `EFC_RESULT` JSON round-trip and timeouts; version-defensive Blender conversion script. Native mesh conversion (STL/OBJ/PLY/GLB/GLTF/3MF via trimesh + an own spec-compliant 3MF reader/writer with per-object colors) that works without Blender; FBX routes through Blender (3MF⇄FBX via STL hop); STEP/IGES return an honest 501 until the Phase 1 CAD kernel. New endpoints `/api/v1/blender/*` and `/api/v1/convert`; capabilities now report formats and Blender status. Inspector gains "Open in Blender" and "Export As…". Includes real-Blender integration tests (skipped when absent).
